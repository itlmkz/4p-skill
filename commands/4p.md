Open the 4p advisory panel and, if a task was given, run it to completion.

The launcher is at `${CLAUDE_PLUGIN_ROOT}/panel/4p.py`. That path is already
resolved for you. Do not search for it.

## Step 1. Check the precondition

The panel lives in Herdr panes, so this session must run inside a Herdr pane.

```bash
test "${HERDR_ENV:-}" = 1 && echo inside-herdr || echo not-in-herdr
```

If it prints `not-in-herdr`, say that the panel needs a Herdr pane and stop. Do
not try to work around it.

## Step 2. Start the panel

Run the launcher. Pass the task through `4PP_TASK` so that quoting cannot break
it, and keep the task text verbatim:

```bash
4PP_TASK="$ARGUMENTS" python3 "${CLAUDE_PLUGIN_ROOT}/panel/4p.py"
```

Rules for this command:

- If `$ARGUMENTS` is empty, drop `4PP_TASK=...` entirely and start the panel
  standing by.
- If the task text contains a double quote, use single quotes around it, or a
  heredoc. Never let the shell expand or glob the task text.
- The panes run pi by default, because 4p is a pi tool and pi panes get their
  write tools removed at launch. Set `4PP_KIND=claude` or another kind to change
  that. Herdr must have that kind available.
- The launcher is idempotent. It reuses a live panel, repairs a drifted label,
  and fills in only what is missing. Never close and recreate a panel to reset it.
- If it fails, print the error it gave you and stop.

## Step 3. Report the panel

Print the panel table from the launcher output: role, pane, agent name, status.
Take the real agent names from that output. Names can carry a numeric suffix,
such as `tester-2`, when a base name is already live in another workspace. Never
assume a name.

If no task was given, stop here. The panel is standing by.

## Step 4. Collect the four reports

If a task was given, the launcher already fanned it out to all four panes. The
AMO got it marked `Full report (4p/report@1):`, so all four answer in the
report contract.

Do not start to implement before you collect and merge the reports. The panel
is the input to your work, not an afterthought.

Collect all four with one call. Give the Bash tool a timeout of 600000 ms,
because the collector waits up to 5 minutes per pane, in parallel:

```bash
python3 "${CLAUDE_PLUGIN_ROOT}/panel/4p.py" --collect
```

It waits for every pane, reads its output, extracts the last `4p/report@1`
block, validates it, and prints one json object:

```json
{
  "tab": "wJ:t3",
  "reports": {
    "contraire":  {"status": "ok", "report": {...}, "errors": []},
    "tester":     {"status": "ok", "report": {...}, "errors": []},
    "reviewer":   {"status": "ok", "report": {...}, "errors": []},
    "bigpicture": {"status": "ok", "report": {...}, "errors": []}
  },
  "all_ok": true
}
```

Read `reports.<role>.status` and `reports.<role>.report` for each role, and
`all_ok` for the whole panel. The command exits 1 when `all_ok` is false. That
is a result, not a crash. Read the json anyway.

A role whose `status` is not `"ok"` failed. Report it as failed, with its status
and `errors`. Never guess what that pane meant, and never fill its seat yourself.

## Step 5. Merge and answer

Present one merged view, not four summaries:

1. Agreements first.
2. Then the single strongest objection per seat.
3. Then your own disposition.

Use the fields that carry the decision: `verdict`, `confidence`,
`findings[].blocks`, `findings[].severity`, `assumptions`, `questions`, and
`could_not_verify`. A finding whose `blocks` is true is a real risk: data loss,
security, a broken deploy, an irreversible choice, or a silent behavior change.
Treat `confidence` below 0.6 as a signal to escalate, not to act.

Anything the panes flagged in `questions` belongs to the owner. Put those
decisions to the user with a recommendation. Never present a decision bare.

## Rapid checkpoint (AMO)

After the merge, the AMO seat is a decision checkpoint. Prompt it with each
decision and design choice as you work, one sentence per decision:

```bash
herdr agent prompt <contraire-name> "Decision: <one sentence>" --wait --timeout 60000
herdr agent read <contraire-name> --source recent-unwrapped --lines 40
```

Take `<contraire-name>` from the launcher output. Checkpoint before an
architecture choice, before more than 20 lines of a new approach, and before
you touch auth, data, payments, or anything irreversible.

The answer is three lines, not json:

```
verdict: yes|yes_but|no_but|no_critical
reason: <one sentence>
watch: <optional watch items>
```

| Verdict | What you do |
| --- | --- |
| `yes` | Proceed. |
| `yes_but` | Proceed. Tell the user the watch item at the end. |
| `no_but` | Apply the fix in `reason` first, then proceed. |
| `no_critical` | Stop all work. Give the user the reason and a recommendation, and wait for the decision. |

Never override a `no_critical`. Do not ask the AMO for a full report on a single
decision. The full report is for the initial task review only.

## Writing rules

The panes advise. You are the only writer. Apply any patch yourself.

Everything the user reads follows these rules:

- English, in Simplified Technical English. One sentence, 20 words maximum.
  Active voice.
- No em dashes.
- Verdict first, then the evidence. Every claim carries a file:line, a command,
  or observed output.
- Do not quote pane json verbatim. Rewrite it.
- Separate blocking findings from nits. Say plainly when something is fine.

## If a pane cannot write

Panel panes are advisors. They are briefed not to change repo files or git state.
If a pane proposes a patch, apply it yourself.
